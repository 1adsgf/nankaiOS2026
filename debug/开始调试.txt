四、启动次序

1. Ctrl+Shift+B 编译。或菜单“终端 -> 运行任务 -> Lab2：编译内核”。
2. 在“运行和调试”的配置下拉框选择“1：宿主 GDB 启动 QEMU（CPU 暂停）”，
   点击绿色启动三角。
   这个配置已经启动 QEMU，因此本流程不要额外运行 make debug。
3. 再选择“2：RISC-V GDB 连接 Lab2（保持暂停）”，点击绿色启动三角。
   客体 CPU 仍暂停在复位处，配置已经设置 kern_init 入口断点。
4. 调试控制台顶部/右侧的会话下拉框选择 RISC-V 会话，输入：
   > c
   等它停在 kern_init。
   这里的 > 必须一并输入，c 必须小写；直接输入 C 或 c 可能被扩展当作 C 表达式求值。
   若客体一直等待，检查宿主会话是否暂停：QEMU 本体暂停时无法回复远端请求。
   先恢复宿主会话，再等待客体响应；若已命中 kern_init，不要再继续一次。
   客体启动配置已设置 set remotetimeout unlimited：宿主断点会暂停整个 QEMU，
   客体 GDB 必须能够等待人工单步完成，不能使用默认的短超时。
   若此前出现 Invalid remote reply、Remote failure reply: E14 或寄存器读取异常，
   先恢复宿主会话，结束客体会话，再停止宿主会话；重新按 2、3、4 启动。
   同时取消 cpu_helper.c 中手动设置的无条件源码断点；host.gdb 会建立过滤
   is_debug 的条件断点，待 lab2-arm ADDRESS 指定目标地址后再命中。
5. 如果要看内核串口输出，运行任务“Lab2：查看 QEMU 串口输出”。
   输出文件是 debug/qemu-serial.log；它不会出现在一个新 QEMU 窗口中。

五、你要自己做的观察

1. 在 RISC-V 会话查看：
   > info registers pc sp ra
   > p/x $satp
   > x/12i $pc

2. 选一条即将执行、还没执行的 ld/sd/lw/sw 等访存指令。
   建议从 kern_init 的第一条栈访问开始，避免已经被缓存的重复访问。
   以你实际反汇编为准，不把固定地址背进报告。
   比如如果选到 sd ra,8(sp)，其有效虚拟地址是 sp+8，先计算：
   > p/x $sp+8
   这是示例用法，其他指令必须按自己的基址寄存器和偏移计算。

3. 记录该指令的 PC、反汇编、有效虚拟地址和 satp。
4. 在“调用堆栈”中选择宿主 GDB 会话，点击暂停。
   调试控制台切换到宿主会话，输入：
   > lab2-arm 你刚算出的虚拟地址
   再继续宿主会话，让 QEMU 恢复运行。
5. 回到 RISC-V 会话，执行一次：
   > si
   如果这次访问触发了真实页表查询，宿主 GDB 将停在 get_physical_address。
   这时 RISC-V GDB 可能仍在等远端响应：QEMU 被另一个调试器暂停，属于正常现象。
6. 切到宿主会话，输入：
   > lab2-context
   使用 next（C 源码级单步）或源码行断点，观察相应赋值完成后的变量：
   addr、env->satp、base、levels、ptidxbits、ptesize、i、ptshift、idx、pte_addr、pte、ppn。
   idx、pte 等局部变量在执行赋值前没有观察意义；优化构建也可能显示 optimized out。
   如果关键变量持续不可见，再单独准备无优化的 QEMU 构建，不要把它误判为翻译失败。
7. 用 bt 看调用栈；观察何时发现叶子 PTE，为什么结束遍历。
   Sv39 支持三级页表，但当前启动页表使用顶层 1 GiB 叶子，不保证走满三级。
8. 在函数成功返回前保存输出指针，例如：
   > set $lab2_pa_out = physical
   > finish
   > p/x *$lab2_pa_out
   这里只读取 QEMU 模拟器写出的结果，不修改页表。
   将实测物理地址与自己的页表计算对照。

宿主 GDB 的 $pc 是宿主 x86-64 指令位置，不是客体 RISC-V PC。
QEMU 源码也注明 get_physical_address 内 env->pc 未必及时同步；
因此客体访存指令的 PC 应在 RISC-V 会话执行 si 之前记录。
pte_addr 是客体物理地址，不是宿主进程指针；不要在宿主 GDB 直接 x/gx pte_addr。
可以观察 QEMU 已读取的 pte 局部变量。

六、手工解释时用的关系

Sv39 虚拟地址索引：VPN2=(VA>>30)&0x1ff，VPN1=(VA>>21)&0x1ff，VPN0=(VA>>12)&0x1ff。
根页表物理地址：satp 的 PPN 字段左移 12 位。
一个 PTE 为 8 字节，所以 PTE 地址=当前页表基址+本级索引*8。
检查 V、R、W、X 等位，区分无效项、非叶子和叶子。
遇到当前框架的顶层叶子时，用其物理基址加虚拟地址低 30 位的偏移组成物理地址。
把实际计算过程写在记录里，不只写“虚拟地址减去一个偏移”。

- remotetimeout=2 时，复现 Invalid remote reply: 4350552330205b72756e6e696e675d
  和 Remote failure reply: E14，客体仍停在 0x1000。
- remotetimeout=600 时，恢复后可正常读取 satp，命中 kern_init，寄存器读取正常。
GDB 17.2 已验证接受 set remotetimeout unlimited，故客体 launch.json 使用无限等待。
该设置不会自动恢复被宿主暂停的 QEMU，仍需在宿主会话继续执行。
