## 三、实验整体逻辑分析

### 2.1 本章节的逻辑主线

本章主要讲解最小可执行内核和启动流程，让Kernel在Qemu模拟器上运行并且能够打印出一行文字。

其流程可以分为以下两条：

1. **内核的内存布局和入口点设置** 操作系统自己做不到"把自己加载到内存"（不能拽着自己的头发离开地面）。所以必须有一个"先锋队"——bootloader。在 QEMU 的 RISC-V 虚拟平台上，这个角色由固化在 `0x80000000` 的 **OpenSBI 固件**担任。编译链接生成的机器指令中，访存地址在链接时就已被写成**绝对地址**（地址相关代码），所以内核必须被放到链接脚本约定的物理内存以地址 `0x80200000`开头的区域上；并且内核镜像的**第一条指令必须落在这个地址上**，OpenSBI 才能把控制权交给操作系统内核。
2. **通过 OpenSBI 封装输入输出函数** 内核里没有 glibc（直接调用C语言库构成了一个**鸡生蛋蛋生鸡**的过程，是不合理的），`printf` 无从谈起。于是必须从**最底层的 SBI 服务**（M 模式）出发，用 `ecall` 一层层封装：`sbi_console_putchar` → `cons_putc` → `cputch` → `cprintf`。

### 2.2 功能的逐步实现

| 步骤  | 实现内容                                                                                             |
| --- | ------------------------------------------------------------------------------------------------ |
| 1   | **链接脚本 `tools/kernel.ld`**：`BASE_ADDRESS = 0x80200000`，`ENTRY(kern_entry)`，指定程序的入口               |
| 2   | **汇编入口 `kern/init/entry.S`**：定义 `kern_entry`，`la sp, bootstacktop` 设置内核栈，`tail kern_init` 跳入 C   |
| 3   | **C 入口 `kern/init/init.c`**：`memset(edata, 0, end - edata)` 清 `.bss`，打印信息，死循环                    |
| 4   | **输出子系统自底向上封装**：`libs/sbi.c` → `kern/driver/console.c` → `kern/libs/stdio.c` + `libs/printfmt.c` |
| 5   | **构建系统 `Makefile` + `tools/function.mk`**：交叉编译 → 链接成 elf → `objcopy` 成 bin → QEMU 加载运行           |
| 6   | **GDB 远程调试**：`make debug` + `make gdb`，跟踪复位向量到内核入口                                               |
