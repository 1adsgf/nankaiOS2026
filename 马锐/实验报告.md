## 三、实验整体逻辑分析

### 3.1 本章节的逻辑主线

本实验围绕“发生中断或异常后，内核如何处理，再如何回到原来的执行流”展开。RISC-V 将中断和异常统称为 Trap：中断一般来自当前指令之外的事件，例如定时器到时；异常与当前指令的执行有关，例如非法指令或断点。

内核先将 Trap 入口写入 stvec。Trap 发生后，硬件记录 sepc、scause 等信息并进入入口；SAVE_ALL 在栈上保存通用寄存器和状态，形成 Trap frame；汇编入口把 Trap frame 地址传给 C 函数 trap；trap_dispatch 根据 cause 分发给处理函数。处理完成后，RESTORE_ALL 恢复现场，sret 根据 sepc 和 sstatus 返回。

### 3.2 功能的逐步实现

1. 将 Lab 2 的 page_init 和 Best-Fit 实现补入 Lab 3 框架，并保留 Lab 3 原有的中断保护代码。
2. 阅读 SAVE_ALL、struct trapframe 和 trap 函数，明确汇编保存的内存布局与 C 结构体的对应关系。
3. 完成 __alltraps 和 RESTORE_ALL，使 Trap frame 能交给 C 函数，并在处理结束后恢复现场。
4. 完成 interrupt_handler 和 exception_handler，处理时钟、非法指令及断点异常。
5. 适配工具链和 QEMU 启动方式，运行自动测试，分析测试结果与覆盖范围。

## 四、实验内容与实现

### 功能模块一：Trap 上下文恢复与 Trap 入口

**负责人：** 2411584-马锐（与 Codex 协作）

#### 模块功能描述与 spec

需要在 `kern/trap/trapentry.S` 中完成 `RESTORE_ALL` 宏和 `__alltraps` 入口。已有 SAVE_ALL 将寄存器和状态保存在栈上的 Trap frame 中。入口需要按 RISC-V 调用约定把当前 sp 中的 Trap frame 地址传给 `trap(struct trapframe *tf)`；trap 返回后进入 __trapret。恢复宏要根据实际布局恢复通用寄存器、sstatus 和 sepc，最后恢复 sp，由已有的 sret 返回。

实现时不能自行改变 SAVE_ALL 与 struct trapframe 的布局，也不能覆盖异常处理函数对 tf->epc 的修改。sp 在恢复其他状态时仍用于定位 Trap frame，因此需要在最后恢复。x0 固定为 0，不需要恢复。

#### 实现与检查

`__alltraps` 使用 `mv a0, sp` 将 Trap frame 地址放入第一个参数寄存器，再调用 trap。RESTORE_ALL 先借用 t0 恢复 sstatus 和 sepc，然后恢复通用寄存器，最后从 Trap frame 恢复 x2/sp。trap 可以修改 tf->epc，恢复代码会取出修改后的值并写入 sepc。

最初单独汇编检查发现旧名称 `sbadaddr` 不被当前汇编器识别。先在临时副本中将其替换为 `stval` 验证；后为完整构建，在项目中作了相同的兼容修改。最终通过了框架中的断点返回与寄存器现场恢复测试。

**负责人：** 2411584-马锐（与 Codex 协作）

#### 模块功能描述与 spec

需要在 `kern/trap/trap.c` 中完成：

```c
void interrupt_handler(struct trapframe *tf);
void exception_handler(struct trapframe *tf);
```

中断处理应从 cause 中区分中断标志和原因编号。时钟中断要设置下一次时钟事件、递增 ticks，并在达到 TICK_NUM 的整数倍时输出统计；达到设定的统计输出次数后调用关机接口。其他中断输出类型或打印现场。

异常处理应区分非法指令和断点异常，输出相应信息并按指令长度更新 tf->epc。其他异常使用 print_trapframe 输出现场。当前实现读取异常指令的前 16 位，根据最低两位区分 2 字节与 4 字节指令，适用于本实验所处理的内核场景；该方式依赖指令地址可读，也不覆盖所有可能的指令长度或异常场景。

指导书提到 SHUTDOWN_AFTER，但当前框架和本地指导书没有给出其数值。实现暂定为 10，即每 100 次中断输出一次，输出 10 次后关机；如课程另有规定，需要调整。

## 六、实验总结与收获

### 对操作系统的理解

1. **Trap 与上下文切换：**硬件记录部分状态并进入入口，但通用寄存器需要软件保存。Trap frame 是汇编与 C 代码共享的现场记录，两者必须使用一致的布局。
2. **特权模式：**本实验中 uCore 在 S 模式运行，OpenSBI 提供 M 模式服务。S 模式通过 SBI 调用设置定时器；sret 的返回特权模式由保存的状态决定，不一定是 U 模式。
3. **CSR：**stvec 保存入口，sepc 记录返回相关地址，scause 表示原因，stval 保存异常相关附加信息；sstatus 和 sie 分别涉及全局状态与具体中断使能。
4. **中断与异常的返回：**时钟中断通常继续被打断的执行流；实验要求对指定异常调整 epc，避免返回后反复执行同一条异常指令。
5. **关闭中断：**alloc_pages 等函数先保存并关闭当前 CPU 的中断，再操作共享结构，最后按原状态恢复。关闭本地中断不能代替多核同步，也不能屏蔽所有同步异常。

### 原理课中重要但本实验未完整覆盖的知识

本实验主要验证纯内核场景，没有完整实现用户态与内核态双向切换；也没有完整实现系统调用、进程调度、缺页异常恢复或多核锁机制。中断嵌套、完整外部设备中断处理及所有指令长度也未在当前测试中全面验证。

### AI 协作开发的经验

先阅读指导书和框架，明确接口、数据布局与边界条件，再让 AI 生成代码。生成后需要检查调用约定、寄存器恢复顺序、返回地址、输出格式以及测试覆盖范围。测试通过说明满足现有测试，不能直接证明所有边界情况都正确。实验过程中遇到的环境兼容和依赖缓存问题，也要结合实际报错分析，而不是直接归因于算法。
